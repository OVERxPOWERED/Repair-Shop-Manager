# API Conventions (v1)

All endpoints live under `/api/v1/`. JSON only. The agent must follow this file exactly and must not invent new response shapes.

## Authentication and context
- `Authorization: Bearer <access_token>` on every request except `auth/*` and the public tracking page.
- `X-Shop-Id: <uuid>` selects the active shop. It must match one of the user's active memberships, otherwise the response is `404`.
- `Accept-Language: en | hi | hi-Latn` selects the language for server-generated text.
- `Idempotency-Key: <uuid>` is required on `POST` endpoints that create jobs, invoices or payments and optional elsewhere. Replaying the same key returns the original response.

## URL style
- Plural nouns, kebab-case: `/jobs/`, `/jobs/{id}/status/`, `/customers/{id}/devices/`.
- Actions that are not CRUD use a verb sub-resource with `POST`: `/invoices/{id}/issue/`, `/invoices/{id}/cancel/`, `/jobs/{id}/deliver/`.
- Trash: `GET /jobs/?deleted=true`, `POST /jobs/{id}/restore/`, `DELETE /jobs/{id}/` (soft), `DELETE /jobs/{id}/permanent/` (permission-gated).

## Success responses
Single object:
```json
{ "data": { "id": "…", "…": "…" } }
```
List (cursor or page pagination, one style per endpoint family, documented in OpenAPI):
```json
{ "data": [ … ], "meta": { "next": "cursor-or-url|null", "count": 120 } }
```

## Errors
Always this shape; the client maps `code` to translated text. Codes are listed in `docs/error-codes.md`.
```json
{ "error": { "code": "invoice.already_issued", "message": "Invoice already issued.", "fields": { "items": ["required"] }, "request_id": "…" } }
```
| HTTP | When |
|---|---|
| 400 | Validation failed (`fields` filled) |
| 401 | Missing/expired token (`auth.token_invalid`) |
| 403 | Authenticated but lacking permission (`permission.denied`) |
| 404 | Not found **or** belongs to another shop |
| 409 | State conflict (`job.invalid_transition`, `sync.conflict`) |
| 422 | Business rule violated (`payment.exceeds_balance`) |
| 429 | Throttled (`rate.limited`, includes `Retry-After`) |
| 5xx | Server error; log with `request_id`, no internals leaked |

## Naming and types
- JSON keys `snake_case`. IDs are UUID strings. Timestamps are ISO 8601 UTC with `Z`. Dates (no time) are `YYYY-MM-DD`.
- Money: integer paise with `_paise` suffix, e.g. `total_paise: 129900`. Never floats. Currency is INR.
- Enums are lowercase snake_case strings; list the allowed values in OpenAPI.
- Phone numbers are E.164 (`+919876543210`). Masked values are returned as `+91XXXXXX3210` when the role lacks `see_customer_phone`.

## Filtering, search, ordering
- Filters as query params via django-filter: `?status=pending&assigned_to=<id>&created_after=2026-10-01`.
- Search: `?q=` (customer name, phone, job number, IMEI last digits).
- Ordering: `?ordering=-updated_at`.

## Concurrency
Editable resources return `version` (integer). Updates send `If-Match: <version>`; mismatch returns `409 conflict`.

## Public endpoints
Only the tracking page (`/t/{token}/`, server-rendered) and OTP endpoints are unauthenticated. They are throttled, return minimal data, and never expose internal IDs.

## Versioning
Breaking changes go to `/api/v2/`. Additive changes (new optional fields) stay in v1. Mobile clients send `X-App-Version`; the server may respond `426` with `app.update_required` when a client is too old.

## Documentation
OpenAPI generated by drf-spectacular at `/api/schema/`; the frontend types are generated from it. Update the schema in the same change as the endpoint.
